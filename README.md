Задание 1. СУБД
Кейс
Крупная строительная компания, которая также занимается проектированием и девелопментом, решила создать правильную архитектуру для работы с данными. Ниже представлены задачи, которые необходимо решить для каждой предметной области.

Какие типы СУБД, на ваш взгляд, лучше всего подойдут для решения этих задач и почему?

1.1. Бюджетирование проектов с дальнейшим формированием финансовых аналитических отчётов и прогнозирования рисков. СУБД должна гарантировать целостность и чёткую структуру данных.

### Тип СУБД: Реляционная СУБД (например, PostgreSQL, MySQL).
Для денег и бюджетов важна железная точность. Реляционные базы данных работают в виде строгих таблиц, где всё связано друг с другом.

1.2. Под каждый девелоперский проект создаётся отдельный лендинг, и все данные по лидам стекаются в CRM к маркетологам и менеджерам по продажам. Какой тип СУБД лучше использовать для лендингов и для CRM? СУБД должны быть гибкими и быстрыми.

### Есть два решения:
Для лендингов: Документо-ориентированная (NoSQL) СУБД (например, MongoDB).

Лендинги могут часто меняться (сегодня собираем только телефон, завтра — имя, почту и комментарий). Документные базы очень гибкие, они позволяют сохранять данные о лидах в любом удобном формате (JSON) без изменения структуры всей базы. К тому же они работают невероятно быстро при записи данных.

Для CRM-системы: Реляционная СУБД (PostgreSQL).

В CRM важны связи между сущностями: клиент - его сделка - менеджер - история оплат. Здесь важна и скорость, и четкая структура, чтобы не перепутать клиентов и их заказы.

1.3. Отдел контроля качества решил создать базу по корпоративным нормам и правилам, обучающему материалу и так далее, сформированную согласно структуре компании. СУБД должна иметь простую и понятную структуру.

### Тип СУБД: Документо-ориентированная (NoSQL) СУБД (например, MongoDB) или встроенная база Wiki-систем.

Статьи, правила и обучающие материалы — это не таблицы с цифрами, это тексты разной длины с картинками и файлами. Документный тип позволяет хранить каждую статью как отдельный «документ». Это даёт простую структуру, где можно легко искать информацию по ключевым словам и менять структуру разделов под изменения в компании.

1.4. Департамент логистики нуждается в решении задач по быстрому формированию маршрутов доставки материалов по объектам и распределению курьеров по маршрутам с доставкой документов. СУБД должна уметь быстро работать со связями.

### Тип СУБД: Графовая СУБД (например, Neo4j).

Логистика — это точки на карте (объекты, склады) и дороги между ними (связи). Графовые базы данных созданы специально для этого: они хранят данные в виде «узлов» и «связей» между ними. Обычная табличная база будет очень долго искать кратчайший путь, а графовая СУБД находит оптимальный маршрут доставки и распределяет курьеров за доли секунды.

Задание 2. Транзакции
2.1. Пользователь пополняет баланс счёта телефона, распишите пошагово, какие действия должны произойти для того, чтобы транзакция завершилась успешно. Ориентируйтесь на шесть действий.

# Создание запроса: Система создает новую транзакцию со статусом «В процессе».
# Проверка баланса и блокировка денег: Банк проверяет, хватает ли у пользователя денег на счете.
# Отправка запроса оператору: Банк посылает защищенный электронный сигнал сотовой компании (например, МТС, Билайн, МегаФон) с сообщением о готовности перевести деньги.
# Подтверждение от оператора: Сотовая компания проверяет, существует ли вообще такой номер телефона и не заблокирован ли он. Если всё в порядке, оператор отвечает банку, чтоперевод принимаем.
# Списание и зачисление средств: Банк окончательно списывает заблокированные деньги со счета пользователя, а сотовая компания мгновенно начисляет на баланс телефона.
# Завершение транзакции: Обе системы записывают в свои базы данных, что операция прошла успешно. Транзакция получает финальный статус «Завершено», а пользователь видит чек и новое состояние баланса.

Задание 3. SQL vs NoSQL
3.1. Напишите пять преимуществ SQL-систем по отношению к NoSQL.

1. Гарантия точности данных (ACID): SQL-базы строго следят за тем, чтобы данные никогда не портились и не терялись. 
2. Строгая структура (Схемы данных): Все данные хранятся в четких таблицах с заранее заданными колонками (как в Excel). Нельзя случайно записать текст туда, где должно быть число. Это защищает базу от хаоса и мусора.
3. Отсутствие дубликатов: Благодаря связям между таблицами, информацию не нужно вводить по два раза.
4. Единый стандартный язык (SQL): Для работы с такими базами используется один универсальный язык запросов — SQL. 
5. Сложнейшие аналитические запросы: SQL-системы позволяют одной командой собирать, группировать и подсчитывать сложные данные из десятков разных таблиц одновременно. Это идеальный инструмент для создания тяжелых финансовых и аналитических отчетов.

Задание 4. Кластеры
Необходимо производить большое количество вычислений при работе с огромным количеством данных, под эту задачу выделено 1000 машин.

На основе какого критерия будете выбирать тип СУБД и какая модель распределённых вычислений здесь справится лучше всего и почему?

1. Критерий выбора СУБД: CAP-теорема

Главным критерием выбора СУБД для кластера из 1000 машин является CAP-теорема (точнее — её часть, отвечающая за горизонтальное масштабирование и отказоустойчивость).

2. Модель распределённых вычислений: MapReduce

Выбираем модель MapReduce.

Модель MapReduce работает по принципу «разделяй и властвуй»:
1. Шаг Map (Распределение): Огромный объем данных разбивается на 1000 маленьких кусочков. Каждая машина получает свою маленькую часть работы и вычисляет результат локально.
2. Шаг Reduce (Сборка): Главный сервер собирает обратно 1000 готовых маленьких ответов от машин и объединяет их в один итоговый результат.
